# 导航与 RSim 测试平台工作记录

目标：修复用户窄道的 RRT 导航，建立可复现的全局 / 局部规划基准，并实现基于 RSim 的多进程导航和独立执行仿真。不得用缩小矩形安全轮廓或暂停物理时间来掩盖失败。

## 验收范围

- 原始窄道及 RRT / Voronoi，分别记录规划成功、闭环到达和失败原因。
- 多种复杂场景：窄门、连续弯道、交错墙、U 形陷阱、杂乱障碍、无解分隔墙，以及直道 / 低速基准；固定地图、出发 / 到达姿态、随机种子和预算。
- 全局基准：多次运行成功率、耗时分位数、路径长度、转角和间距；独立校验返回路线。失败也计入报告。
- 局部基准：实际到达、实体碰撞、速度、跟踪误差、转向变化、间距、优化与执行耗时、超时 / 制动次数。包括不理想全局路线、100 / 400 ms 计算延迟、传感器迟到 / 中断及恢复。
- RSim 导航组件：全局规划、局部优化与执行分离；有界最新快照、地图 / 任务版本、原生车型命令、期限、陈旧结果拒绝、独立执行检查与失联制动。核心 pyrobo 导入不强制加载 RSim。
- 测试平台：相同组件可本地 / 多进程部署，真实进程验证；物理时间持续前进，延迟可注入，场景与报告可保存、复跑和绘图。
- 根据基准和剖析改进性能、路径适应性与参数敏感性，保留改动前后的原始报告。完整 pytest、CLI 和实际图形检查。

## 方法参考

- [OMPL benchmark](https://ompl.kavrakilab.org/benchmark.html)：相同问题、多次独立运行、相同预算，以及路径质量和独立正确性检查。
- [DWA 原论文入口](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance)：动力学约束与可停止性。
- [Nav2 Regulated Pure Pursuit](https://github.com/ros-navigation/navigation2/tree/main/nav2_regulated_pure_pursuit_controller)：速度、曲率与障碍距离的联合调节，作为设计参考，不复制其栅格碰撞假设。

## 已交付与验证（2026-10-29）

- `benchmarks/navigation` 提供八张连续几何地图、重复全局基准、固定 dt 闭环、真实时间故障注入、保存场景导入、原始报告和绘图。同步闭环与真实时间实验的结论明确分开。
- `pyrobo.integrations.rsim.NavigationStack` 使用真实 RSim 的三个独立 worker；仿真在主进程持续推进。已验证本地和多进程组件图、原生 Ackermann 命令、DDS / shared-mapping 和退出清理。
- `runtime.leases.LeaseExecutor` 保留原始提案期限，按任务 / 地图版本拒绝旧结果，独立检查完整执行租期和制动，使用有界实际命令历史外推允许的延迟观测；未知历史或陈旧输入停机。
- RRT 桥接采样与矩形缓存、显式自适应额外间距、自动终点入射段减少窄道参数耦合。DWA 分离前视 / 预测目标，提前拒绝一周期制动不安全的候选，修正同代价转角、重规划转向方向及小幅姿态对齐，增加有限安全退让。
- 原始窄道两规划器自动配置各 20/20 规划通过，实际 Web 和 RSim 到达。RRT 同预算桥接对照为 17/20 → 20/20；部分其他地图耗时增加。
- 400 ms 窄道卡顿最初两版未到达，保留失败数据。超时保持实测转角、撤掉速度参考后，两次报告均约 29.6 s 到达，各拒绝 23 个迟到结果；状态 / 动态地图中断均制动并恢复。
- 全量 256 项 pytest 通过；后加真实窄道卡顿用例单独通过，共 257 项。真实 Edge、Pygame CLI、保存场景 CLI、LAN HTTP 和图像检查完成。

## 保留的限制

最终七地图 × 两车型 × 两规划器闭环为 27/28 到达、零实体碰撞；`slalom / voronoi / ackermann` 在 700 步内未到达。XY 路线不是汽车可达性证明，有限退让无法解决任意局部最优。低速卡顿直道没有左右摆动，但期限制动仍造成速度波动。Python / DDS 为软实时，不能声称所有控制都低于 100 ms 或跨任意传感器中断无停车。

详细指标、失败样本、原始 JSON 和复跑说明以[实测报告](../reports/navigation/README.md)为准；没有缩小车体、改写数值快照或暂停故障实验的物理时间。
